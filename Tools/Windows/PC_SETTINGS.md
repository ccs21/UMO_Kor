# 우타마크로스 PC 설정

`UMO_PC_Settings.exe`를 게임 실행 파일과 같은 폴더에 두고 실행합니다.
저장한 설정은 `UMO_PC_Settings.ini`에 기록되며 게임을 다시 실행하면 적용됩니다.
설정 변경 전 파일은 `.ini.bak`으로 보관합니다. 세이브나 추가 데이터는 변경하지 않습니다.
별도의 **검수용 자원 충전** 버튼을 실행하는 경우에만 아래 절차로 테스트 복사본을 변경합니다.

## 검수용 자원 충전

1. 게임과 Unity Editor를 종료하고 설정 도구 맨 아래의 `검수용 테스트 프로필 / 자원 충전`을 누릅니다.
2. 원본 프로필을 선택해 `선택 프로필 테스트 복사`를 누릅니다. 생성된 600000000번대 프로필 번호를 확인합니다.
3. `[테스트]` 복사본을 선택해 `소재·재화 최대 충전`을 누릅니다.
4. 게임을 켜고 프로필 선택에서 해당 번호를 선택합니다. 원본 프로필 선택은 자동 변경하지 않습니다.
5. 다시 충전하려면 게임을 종료하고 같은 테스트 프로필에 3번을 반복합니다.

가정석 총 9,999개(무료분 보존), UC 99,999,999개, 강화/발키리 소재 각각 99,999개,
에피소드/의상 소재 각각 9,999개까지 채웁니다. 기존 초과 수량은 줄이지 않습니다.
세이브에 정의된 소재 슬롯만 변경하며, 특수 아이템·티켓·EN·랭크·곡 기록·튜토리얼·보유 의상은 변경하지 않습니다.
Android 및 원본 프로필에는 적용하지 않습니다.

충전 전 `저장 루트/PcTestBackups/<프로필 번호>/<시각-고유번호>/`에 프로필 전체와
로컬 세이브를 백업합니다. 복구 시 게임을 종료하고 `Profile`의 파일을 해당 `Profiles/<번호>`에,
`<번호>_save.bin`이 있으면 `SaveData`에 복원합니다. 다른 번호의 프로필과 섞지 마세요.

## 이동 롱노트

Windows에서는 시작 레인의 키를 유지하고 최종 끝 타이밍에 놓습니다.
중간의 레인 이동은 시각적으로 유지되지만 다른 키로 갈아탈 필요는 없습니다.
조기 해제/늦은 해제 실패와 기존 판정 보조 설정은 유지됩니다. Android 처리에는 적용하지 않습니다.

## 기본 조작

화면 왼쪽부터 순서대로 다음과 같습니다.

| 구분 | 키보드 | 게임패드 (XInput) |
| --- | --- | --- |
| 4레인 | S D K L | 십자키 왼쪽·위쪽, Y, B |
| 6레인 | S D F J K L | 십자키 왼쪽·위쪽·오른쪽, X, Y, B |
| 스킬 | Space | LB / RB / LT / RT 중 하나 |

4레인과 6레인의 배치를 따로 변경할 수 있습니다. 같은 모드 안에서 레인 키 중복 및
스킬과의 중복은 저장할 수 없습니다. 게임패드는 처음 감지한 XInput 장치를 사용하며,
연결이 끊어지면 다른 연결 장치를 찾습니다. DirectInput 전용 모드는 지원하지 않습니다.
키보드와 게임패드로 같은 레인을 누른 경우 둘 다 놓아야 해제됩니다.

이 도구는 레인·스킬 매핑을 설정합니다. 왼쪽 스틱 커서 이동/A 버튼 메뉴 선택은
아직 이번 구현에 포함되지 않았습니다. 메뉴는 터치나 마우스로 조작해 주세요.

## PC 판정 보조

- 원본: 추가 허용 시간 0ms.
- 약하게 (기본): 앞뒤 각각 15ms 추가.
- 넉넉하게: 앞뒤 각각 30ms 추가.

각 판정 등급과 노트가 지나가서 실패가 되는 경계에 동일하게 적용합니다.
스킬의 판정 보정은 별도로 유지됩니다. 자동 성공, 강제 실패 해제,
우타히메/초 우타히메 모드 진입 조건 변경은 하지 않습니다.
보조를 사용한 점수와 클리어도 기존 프로필에 기록되며 별도 기록으로 분리하지 않습니다.
Android와 Unity Editor 실행의 판정은 바뀌지 않습니다.

## 리전 고 1 저부하 설정

우선 1280×800, 60fps, 저부하를 선택해 테스트합니다. 1280×720과 1920×1080도 선택 가능합니다.
저부하는 안티앨리어싱·실시간 그림자·이방성 필터를 끕니다. 뽑기 화면의 강제 8배 AA도
저부하에서 사용하지 않습니다. UI 아틀라스 해상도나 텍스처 변환 형식은 건드리지 않습니다.
고유 연출용 셰이더 효과를 전부 끄는 설정은 아닙니다.
30fps는 전력 절약용 선택지이며 리듬게임 입력/화면 갱신 감각이 달라질 수 있어 60fps를 권합니다.
실제 기기의 평균/최저 프레임, 전력 소모는 아직 측정하지 않았습니다.

## 개발 및 검사

`Tools/Build/Build-Windows.ps1`은 게임과 설정 도구를 함께 빌드합니다.
게임이 실행 중이면 `-Output`으로 별도 폴더를 지정하세요. 원본 데이터나 세이브를 복사하지 않습니다.
설정 도구만 빌드하려면 `Tools/Windows/Build-PcSettings.ps1 -OutputDirectory <게임 폴더>`를 실행합니다.
도구 컴파일에는 Windows의 .NET Framework 4.x C# 컴파일러가 필요합니다.

- `Tools/Windows/Test-PcSettings.ps1`: 기본값, 키 충돌, 파일 저장/백업,
  4/6레인 매핑, 입력 경계, PC/Android 판정 등급 및 실패 경계 검사.
- `python Tools/Windows/test_pc_hold_effects.py`: 실제 입력 콜백을 추출해
  두 레인의 롱노트 이펙트가 일반 누름 이펙트로 덮이지 않는지 검사.
- `python Tools/Windows/test_pc_tail_rules.py`: Android 롱노트 끝 처리 보존 검사.

자동 테스트는 실제 컨트롤러/레인 배치/프레임 성능이나 렌더링 검증을 대신하지 않습니다.
실기 재시험: 4/6레인 각각 입력, 두 롱노트 동시 유지 및 따로 떼기, 화살표 꼬리,
초 우타히메 모드, 게임패드 분리/재연결, 창 전환 후 입력 해제, 800p 전체화면/터치 정렬.
